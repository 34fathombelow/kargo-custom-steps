# cdk8s-synth-python

Synthesizes Kubernetes YAML from a Python [cdk8s](https://cdk8s.io) app in the promotion workdir, the way the
built-in `helm-template` and `kustomize-build` steps do for Helm and Kustomize. Later steps, such as a policy gate or
`manifest-diff`, use the rendered files.

The same step exists for other cdk8s languages, each with its own image: [`cdk8s-synth`](../cdk8s-synth/README.md) (TypeScript), [`cdk8s-synth-go`](../cdk8s-synth-go/README.md) (Go).

## Prerequisites

Beyond the [common prerequisites](../../../../README.md#prerequisites):

| | |
|---|---|
| Cluster add-ons | None |
| Reachable services | None |
| Accounts / credentials | None. Private package registries are not supported |
| Kargo capabilities | None |
| Network egress | PyPI (`pypi.org`, `files.pythonhosted.org`), for `uv sync` |
| Inputs | The cdk8s app in the workdir, from an earlier `git-clone` step, with its `cdk8s.yaml` (`language: python`), `uv.lock` (from [uv](https://docs.astral.sh/uv/), which `cdk8s init python-app` sets up) and generated `imports/` committed |

## Image

`ghcr.io/34fathombelow/cdk8s-python:2.207.73`, built from [`docker/cdk8s-python/Dockerfile`](../../../../docker/cdk8s-python/Dockerfile) and published by this repo's
GitHub Actions:

```dockerfile
# Node.js, the cdk8s CLI, Python and uv for the Kargo cdk8s-synth-python custom
# step, which renders Python cdk8s apps (uv sync + cdk8s synth). The cdk8s
# Python bindings also need Node.js at run time (jsii).
# jq and yq turn the rendered manifests into the step's JSON output.
# renovate: datasource=npm depName=cdk8s-cli
ARG CDK8S_PYTHON_VERSION=2.207.73
# renovate: datasource=docker depName=node versioning=node
ARG NODE_VERSION=26.12.1
# renovate: datasource=docker depName=alpine
ARG ALPINE_VERSION=3.24
# renovate: datasource=docker depName=ghcr.io/astral-sh/uv
ARG UV_VERSION=0.13.6
# renovate: datasource=docker depName=mikefarah/yq
ARG YQ_VERSION=4.54.1

FROM ghcr.io/astral-sh/uv:${UV_VERSION} AS uv
FROM mikefarah/yq:${YQ_VERSION} AS yq

FROM node:${NODE_VERSION}-alpine${ALPINE_VERSION}
ARG CDK8S_PYTHON_VERSION
LABEL org.opencontainers.image.source=https://github.com/34fathombelow/kargo-custom-steps \
      org.opencontainers.image.description="cdk8s CLI with Node.js, Python and uv for Python cdk8s apps, for the Kargo cdk8s-synth custom steps" \
      org.opencontainers.image.version=${CDK8S_PYTHON_VERSION}
RUN apk add --no-cache bash ca-certificates jq python3 && \
    npm install -g cdk8s-cli@${CDK8S_PYTHON_VERSION} && \
    npm cache clean --force
COPY --from=uv /uv /usr/local/bin/uv
COPY --from=yq /usr/bin/yq /usr/local/bin/yq
# Custom steps run as 65532: npm, uv and the app write caches under a writable /tmp.
ENV HOME=/tmp \
    npm_config_cache=/tmp/.npm \
    npm_config_update_notifier=false \
    npm_config_fund=false \
    npm_config_audit=false \
    UV_CACHE_DIR=/tmp/.uv \
    UV_PYTHON_DOWNLOADS=never \
    UV_PYTHON=/usr/bin/python3 \
    JSII_SILENCE_WARNING_UNTESTED_NODE_VERSION=1
USER 65532:65532
```

## Config

| Key | Type | Required | Default | Description |
|---|---|---|---|---|
| `path` | string | yes | — | Workdir-relative app directory containing `cdk8s.yaml` and `uv.lock`, e.g. `./src/deploy/cdk8s` |
| `outPath` | string | yes | — | Workdir-relative directory to write to, with one `<chart>.k8s.yaml` per chart. Replaced if it exists |
| `env` | map | no | `{}` | Environment variables for the app (`os.environ`), e.g. `{ENVIRONMENT: prod}`, so one app can render per-Stage settings. Values are passed as strings |

## Outputs

| Key | Type | Description |
|---|---|---|
| `language` | string | The app's language, from its `cdk8s.yaml` |
| `outPath` | string | Where the manifests were written |
| `count` | number | Number of Kubernetes objects rendered |
| `files` | list | Files written (workdir-relative) |
| `resources` | list | `{kind, name, namespace}` for each object |
| `error` | string | Why the step failed, e.g. the first error with its file and line; empty on success |

## Example

Render the app with the Freight's image, passed to the app through `env`:

```yaml
steps:
- uses: git-clone
  config:
    repoURL: https://github.com/example/deploy.git
    checkout:
    - branch: main
      path: ./src
- uses: cdk8s-synth-python
  as: render
  config:
    path: ./src/cdk8s
    outPath: ./out
    env:
      ENVIRONMENT: ${{ ctx.stage }}
      IMAGE: ghcr.io/example/app:${{ imageFrom("ghcr.io/example/app").Tag }}
```

To show reviewers what a promotion changes, diff `./out` against the previous render (for example the manifests
committed to an environment branch, checked out by `git-clone`) with
[`manifest-diff`](../../release-insight/manifest-diff/README.md).

## Notes

- The step installs the app's dependencies with `uv sync --frozen` and then runs `cdk8s synth` with the cdk8s CLI from the
  image. It checks that `cdk8s.yaml` says `language: python` and names the right step otherwise. Java is not supported.
- The step runs your app's code, as `cdk8s synth` always does, so point it only at repositories you trust.
- A committed lockfile is required, which keeps renders reproducible. Commit the generated `imports/` too, so the step
  needs no `cdk8s import` and no access to Kubernetes API schemas.
- Wrong types fail the step: the cdk8s Python bindings check argument types when the app runs, so a wrong type raises a `TypeError`. The first error, with its file and line, is shown in the `error` output.
- `env` values are exported as separate variables, never evaluated by a shell, so any characters are safe.
- Tested: harness fixtures in [`test/fixtures/cdk8s-synth-python`](../../../../test/fixtures/cdk8s-synth-python).

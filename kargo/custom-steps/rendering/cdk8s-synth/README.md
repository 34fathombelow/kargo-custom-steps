# cdk8s-synth

Synthesizes Kubernetes YAML from a TypeScript [cdk8s](https://cdk8s.io) app in the promotion workdir, the way the
built-in `helm-template` and `kustomize-build` steps do for Helm and Kustomize. Later steps, such as a policy gate or
`manifest-diff`, use the rendered files.

The same step exists for other cdk8s languages, each with its own image: [`cdk8s-synth-python`](../cdk8s-synth-python/README.md) (Python), [`cdk8s-synth-go`](../cdk8s-synth-go/README.md) (Go).

## Prerequisites

Beyond the [common prerequisites](../../../../README.md#prerequisites):

| | |
|---|---|
| Cluster add-ons | None |
| Reachable services | None |
| Accounts / credentials | None. Private package registries are not supported |
| Kargo capabilities | None |
| Network egress | The npm registry (`registry.npmjs.org`), for `npm ci` |
| Inputs | The cdk8s app in the workdir, from an earlier `git-clone` step, with its `cdk8s.yaml` (`language: typescript`), `package-lock.json` and generated `imports/` committed |

## Image

`ghcr.io/34fathombelow/cdk8s-typescript:2.207.73`, built from [`docker/cdk8s-typescript/Dockerfile`](../../../../docker/cdk8s-typescript/Dockerfile) and published by this repo's
GitHub Actions:

```dockerfile
# Node.js and the cdk8s CLI for the Kargo cdk8s-synth custom step, which
# renders TypeScript cdk8s apps (npm ci + cdk8s synth).
# jq and yq turn the rendered manifests into the step's JSON output.
# renovate: datasource=npm depName=cdk8s-cli
ARG CDK8S_TYPESCRIPT_VERSION=2.207.73
# renovate: datasource=docker depName=node versioning=node
ARG NODE_VERSION=26.12.1
# renovate: datasource=docker depName=alpine
ARG ALPINE_VERSION=3.24
# renovate: datasource=docker depName=mikefarah/yq
ARG YQ_VERSION=4.54.1

FROM mikefarah/yq:${YQ_VERSION} AS yq

FROM node:${NODE_VERSION}-alpine${ALPINE_VERSION}
ARG CDK8S_TYPESCRIPT_VERSION
LABEL org.opencontainers.image.source=https://github.com/34fathombelow/kargo-custom-steps \
      org.opencontainers.image.description="cdk8s CLI with Node.js for TypeScript cdk8s apps, for the Kargo cdk8s-synth custom steps" \
      org.opencontainers.image.version=${CDK8S_TYPESCRIPT_VERSION}
RUN apk add --no-cache bash ca-certificates jq && \
    npm install -g cdk8s-cli@${CDK8S_TYPESCRIPT_VERSION} && \
    npm cache clean --force
COPY --from=yq /usr/bin/yq /usr/local/bin/yq
# Custom steps run as 65532: npm writes a cache under a writable /tmp.
ENV HOME=/tmp \
    npm_config_cache=/tmp/.npm \
    npm_config_update_notifier=false \
    npm_config_fund=false \
    npm_config_audit=false
USER 65532:65532
```

## Config

| Key | Type | Required | Default | Description |
|---|---|---|---|---|
| `path` | string | yes | — | Workdir-relative app directory containing `cdk8s.yaml` and `package-lock.json`, e.g. `./src/deploy/cdk8s` |
| `outPath` | string | yes | — | Workdir-relative directory to write to, with one `<chart>.k8s.yaml` per chart. Replaced if it exists |
| `env` | map | no | `{}` | Environment variables for the app (`process.env`), e.g. `{ENVIRONMENT: prod}`, so one app can render per-Stage settings. Values are passed as strings |

## Outputs

| Key | Type | Description |
|---|---|---|
| `language` | string | The app's language, from its `cdk8s.yaml` |
| `outPath` | string | Where the manifests were written |
| `count` | number | Number of Kubernetes objects rendered |
| `files` | list | Files written (workdir-relative) |
| `resources` | list | `{kind, name, namespace}` for each object |
| `error` | string | Why the step failed, e.g. the first error with its file and line; empty on success |

## Example

Render the app with the Freight's image, passed to the app through `env`:

```yaml
steps:
- uses: git-clone
  config:
    repoURL: https://github.com/example/deploy.git
    checkout:
    - branch: main
      path: ./src
- uses: cdk8s-synth
  as: render
  config:
    path: ./src/cdk8s
    outPath: ./out
    env:
      ENVIRONMENT: ${{ ctx.stage }}
      IMAGE: ghcr.io/example/app:${{ imageFrom("ghcr.io/example/app").Tag }}
```

To show reviewers what a promotion changes, diff `./out` against the previous render (for example the manifests
committed to an environment branch, checked out by `git-clone`) with
[`manifest-diff`](../../release-insight/manifest-diff/README.md).

## Notes

- The step installs the app's dependencies with `npm ci` and then runs `cdk8s synth` with the cdk8s CLI from the
  image. It checks that `cdk8s.yaml` says `language: typescript` and names the right step otherwise. Java is not supported.
- The step runs your app's code, as `cdk8s synth` always does, so point it only at repositories you trust.
- A committed lockfile is required, which keeps renders reproducible. Commit the generated `imports/` too, so the step
  needs no `cdk8s import` and no access to Kubernetes API schemas.
- Wrong types fail the step: `ts-node` type-checks the app before running it, so a wrong type is a compile error. The first error, with its file and line, is shown in the `error` output.
- `env` values are exported as separate variables, never evaluated by a shell, so any characters are safe.
- Tested: harness fixtures in [`test/fixtures/cdk8s-synth`](../../../../test/fixtures/cdk8s-synth).

# jsonnet-render

Renders [Jsonnet](https://jsonnet.org) into Kubernetes YAML in the promotion workdir, the way the built-in
`helm-template` and `kustomize-build` steps do for Helm and Kustomize. Later steps, such as a policy gate,
use the rendered files.

## Prerequisites

Beyond the [common prerequisites](../../../../README.md#prerequisites):

| | |
|---|---|
| Cluster add-ons | None |
| Reachable services | None |
| Accounts / credentials | None. With `jbInstall` and private dependencies, git credentials the image's `git` can use |
| Kargo capabilities | None |
| Network egress | Only with `jbInstall: true`: the dependency hosts in `jsonnetfile.json` (usually `github.com`) |
| Inputs | The Jsonnet sources in the workdir, from an earlier `git-clone` step |

## Image

`ghcr.io/34fathombelow/jsonnet:v0.22.0`, built from [`docker/jsonnet/Dockerfile`](../../../../docker/jsonnet/Dockerfile) and published by this repo's
GitHub Actions:

```dockerfile
# go-jsonnet and jsonnet-bundler, built from source: no official multi-arch image.
# yq converts jsonnet's JSON output into readable YAML manifests.
# renovate: datasource=github-releases depName=google/go-jsonnet
ARG JSONNET_VERSION=v0.22.0
# renovate: datasource=github-releases depName=jsonnet-bundler/jsonnet-bundler
ARG JB_VERSION=v0.6.0
# renovate: datasource=docker depName=golang
ARG GO_VERSION=1.27.2
# renovate: datasource=docker depName=alpine
ARG ALPINE_VERSION=3.24.2
# renovate: datasource=docker depName=mikefarah/yq
ARG YQ_VERSION=4.54.1

FROM golang:${GO_VERSION}-alpine AS build
ARG JSONNET_VERSION
ARG JB_VERSION
RUN CGO_ENABLED=0 go install github.com/google/go-jsonnet/cmd/jsonnet@${JSONNET_VERSION} && \
    CGO_ENABLED=0 go install github.com/jsonnet-bundler/jsonnet-bundler/cmd/jb@${JB_VERSION}

FROM mikefarah/yq:${YQ_VERSION} AS yq

FROM alpine:${ALPINE_VERSION}
LABEL org.opencontainers.image.source=https://github.com/34fathombelow/kargo-custom-steps \
      org.opencontainers.image.description="jsonnet + jb for the Kargo jsonnet-render custom step"
RUN apk add --no-cache bash ca-certificates git jq
COPY --from=build /go/bin/jsonnet /go/bin/jb /usr/local/bin/
COPY --from=yq /usr/bin/yq /usr/local/bin/yq
ENV HOME=/tmp
USER 65532:65532
```

## Config

| Key | Type | Required | Default | Description |
|---|---|---|---|---|
| `path` | string | yes | — | Workdir-relative entry file, e.g. `./src/deploy/main.jsonnet` |
| `outPath` | string | yes | — | A path ending in `.yaml`/`.yml` gets one multi-document file. Anything else is a directory with one `<kind>-<name>.yaml` per object. Replaced if it exists |
| `extVars` | map | no | `{}` | External string variables (`std.extVar`). Values are passed as strings |
| `tlaVars` | map | no | `{}` | Top-level string arguments, when the entry file evaluates to a function |
| `jpath` | list | no | `[]` | Workdir-relative library directories (`-J`) |
| `jbInstall` | bool | no | `false` | Run `jb install` next to the entry file first. Needs its `jsonnetfile.json`; `vendor/` is then added to `jpath` |

The entry file may evaluate to a Kubernetes object, a `List`, an array, or an object whose values are any of these
(the common `{deployment: ..., service: ...}` layout). Nested combinations are flattened.

## Outputs

| Key | Type | Description |
|---|---|---|
| `outPath` | string | Where the manifests were written |
| `count` | number | Number of Kubernetes objects rendered |
| `files` | list | Files written (workdir-relative) |
| `resources` | list | `{kind, name, namespace}` for each object |

## Example

```yaml
steps:
- uses: git-clone
  config:
    repoURL: https://github.com/example/deploy.git
    checkout:
    - branch: main
      path: ./src
- uses: jsonnet-render
  as: render
  config:
    path: ./src/app/main.jsonnet
    jpath:
    - ./src/lib
    outPath: ./src/rendered/${{ ctx.stage }}
    extVars:
      image: ghcr.io/example/app:${{ imageFrom("ghcr.io/example/app").Tag }}
      env: ${{ ctx.stage }}
```

## Notes

- Deterministic and idempotent: the same sources and variables always produce the same files, and `outPath` is replaced.
- `extVars`/`tlaVars` go to jsonnet as separate arguments, never through a shell, so any characters are safe.
- `jsonnet` errors (undefined variables, syntax errors) are shown in the step message as-is.
- Tested: harness fixtures in [`test/fixtures/jsonnet-render`](../../../../test/fixtures/jsonnet-render). `jbInstall`
  needs network, so the fixtures only cover its misconfiguration path.

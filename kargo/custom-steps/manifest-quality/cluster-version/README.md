# cluster-version

Looks up the Kubernetes version a cluster actually runs, so later steps can target it instead of a version number
someone has to keep updating in every Stage. Feed its `version` output to [`deprecated-apis`](../deprecated-apis)
(`k8sVersion`), or to `helm-template` (`kubeVersion`).

The version comes from Argo CD. Its application controller already tracks every cluster it manages, and publishes
each one as a Prometheus metric on the `argocd-metrics` Service, with no authentication:

```text
argocd_cluster_info{k8s_version="v1.35.5",name="custom-steps-agent",server="http://cluster-custom-steps-agent:8001"} 1
```

The step reads that metric. It needs no capability, token or CA. (Asking the cluster's API server directly doesn't work
from a custom step: step containers get no Kubernetes token, and k3s and EKS refuse anonymous `/version`.)

> [!IMPORTANT]
> **The Argo CD agent must run in the same namespace as the Kargo agent's promotion controller** (on Akuity, both in
> `akuity` on the agent cluster). The step reaches `http://argocd-metrics:8082/metrics` by its short name, which only
> resolves in the promotion pod's own namespace. If Argo CD runs elsewhere, set `metricsURL`.

## Prerequisites

Beyond the [common prerequisites](../../../../README.md#prerequisites):

| | |
|---|---|
| Cluster add-ons | **An Argo CD agent in the same namespace as the `custom-steps` Kargo agent's promotion controller**, on the agent cluster where promotion pods run. It reports the cluster it manages |
| Reachable services | Argo CD's `argocd-metrics` Service, port 8082. Akuity's network policy for the application controller allows it from any namespace |
| Accounts / credentials | None |
| Kargo capabilities | None |
| Network egress | None (in-namespace only) |
| Inputs | None |

## Config

| Key | Type | Required | Default | Description |
|---|---|---|---|---|
| `cluster` | string | no | the only cluster in the metrics | Argo CD cluster name to report. Each Akuity Argo CD agent reports just its own cluster, so this is needed only when one controller manages several |
| `metricsURL` | string | no | `http://argocd-metrics:8082/metrics` | Argo CD application-controller metrics URL, when Argo CD doesn't run in the promotion pod's namespace |

## Outputs

| Key | Type | Description |
|---|---|---|
| `version` | string | `vX.Y.Z` without vendor suffixes, e.g. `v1.34.2`. **Use this one** in expressions: it starts with `v`, so Kargo's template engine keeps it a string |
| `k8sVersion` | string | The version as Argo CD reports it, e.g. `v1.34.2+k3s1` |
| `minor` | string | `"X.Y"`, e.g. `"1.34"`. Don't pass it through `${{ }}` on its own: the template engine re-parses `1.30` as the number `1.3` |
| `cluster` | string | The Argo CD cluster name |
| `server` | string | The cluster's API server URL, as Argo CD knows it |
| `source` | string | The metrics URL that answered |
| `error` | string | Only when the step fails: why |

## Example

```yaml
steps:
- uses: cluster-version
  as: cluster
- uses: deprecated-apis
  config:
    path: ./out
    k8sVersion: ${{ outputs['cluster'].version }}   # inside a PromotionTask: task.outputs['cluster'].version
```

## Try it

Demo project `custom-steps-manifest-quality` ([kargo/projects/manifest-quality](../../../projects/manifest-quality)):

| Stage | What it does | Expected |
|---|---|---|
| `cluster-version-lookup` | Only runs `cluster-version` | Passes. The `cluster` step's output shows the agent cluster's version |
| `cluster-version-pass` | Looks up the version, then runs `deprecated-apis` against it on manifests that use only current APIs | Passes |
| `cluster-version-blocked` | Looks up the version, then runs `deprecated-apis` against it on manifests with an `autoscaling/v2beta2` HPA | Blocked on any supported Kubernetes version (the API was removed in 1.26) |

## Notes

- Read-only and idempotent, so retries are safe.
- A new promotion pod's first connections can be refused for a moment while the cluster's network policy catches up
  with it, so the step retries "connection refused" for up to about 30 seconds. Other errors fail right away.
- The version is as fresh as Argo CD's cluster cache, which refreshes on its own schedule. After a cluster upgrade it
  may lag briefly.
- Tested: harness fixtures in [`test/fixtures/cluster-version`](../../../../test/fixtures/cluster-version), against a fake
  metrics endpoint with one cluster, several clusters (in different label orders), an `X.Y`-only version, and no
  `argocd_cluster_info` at all.

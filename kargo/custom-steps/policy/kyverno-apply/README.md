# kyverno-apply

Checks rendered manifests against Kyverno policies with the Kyverno CLI before they are committed or synced, so a
promotion fails *before* admission control would reject the sync.

## Prerequisites

Beyond the [common prerequisites](../../../../README.md#prerequisites):

| | |
|---|---|
| Cluster add-ons | None. The CLI evaluates policy files; Kyverno does not need to be installed anywhere |
| Reachable services | None |
| Accounts / credentials | None (git credentials only if the policy repo is private, for the `git-clone` step) |
| Kargo capabilities | None |
| Network egress | None |
| Inputs | Rendered manifests (e.g. `./out` from `helm-template` / `kustomize-build`) and policy files (e.g. from `git-clone`) in the workdir |

## Image

`ghcr.io/34fathombelow/kyverno:v1.19.1`, built from [`docker/kyverno/Dockerfile`](../../../../docker/kyverno/Dockerfile) and published by this repo's
GitHub Actions:

```dockerfile
# Kyverno CLI plus a shell and jq, so kyverno-apply can summarize the policy report.
# renovate: datasource=docker depName=ghcr.io/kyverno/kyverno-cli
ARG KYVERNO_VERSION=v1.19.1
# renovate: datasource=docker depName=alpine
ARG ALPINE_VERSION=3.24.2

FROM ghcr.io/kyverno/kyverno-cli:${KYVERNO_VERSION} AS kyverno

FROM alpine:${ALPINE_VERSION}
LABEL org.opencontainers.image.source=https://github.com/34fathombelow/kargo-custom-steps \
      org.opencontainers.image.description="Kyverno CLI for the Kargo kyverno-apply custom step"
RUN apk add --no-cache bash ca-certificates jq
COPY --from=kyverno /ko-app/kubectl-kyverno /usr/local/bin/kyverno
ENV HOME=/tmp
USER 65532:65532
```

## Config

| Key | Type | Required | Default | Description |
|---|---|---|---|---|
| `path` | string | yes | — | Workdir-relative manifest file or directory |
| `policyPath` | string | yes | — | Workdir-relative policy file or directory (tested with `ClusterPolicy`) |
| `failOn` | string | no | `fail` | `fail`: block on failed or errored rules. `warn`: also block on warnings (Audit-mode policies are reported as warnings) |

## Outputs

| Key | Type | Description |
|---|---|---|
| `passed` | bool | Whether the promotion was allowed through |
| `summary` | object | `{pass, fail, warn, error, skip}` rule-result counts |
| `violations` | list | Up to 200 `{policy, rule, result, resource, message}` for every `fail`, `warn` and `error` result. `resource` is `Kind/namespace/name` |

When `passed` is false the step **fails** and the promotion stops; the output is still recorded so the promotion shows
which rules failed.

## Example

```yaml
steps:
- uses: git-clone
  config:
    repoURL: https://github.com/example/platform-policies.git
    checkout:
    - branch: main
      path: ./policies
- uses: helm-template
  config:
    path: ./src/charts/my-app
    valuesFiles:
    - ./src/charts/my-app/values-${{ ctx.stage }}.yaml
    outPath: ./out
- uses: kyverno-apply
  as: kyverno
  config:
    path: ./out
    policyPath: ./policies/kyverno
```

## Notes

- Read-only and idempotent, so retries are safe.
- The CLI prints deprecation warnings for `kyverno.io/v1` `ClusterPolicy` on stdout ahead of the JSON report (Kyverno 1.19
  recommends the CEL-based `policies.kyverno.io` kinds). The step strips them; the policies still work.
- Resources without a namespace are reported in `default`, as the CLI does.
- **Not supported yet: a `cluster` mode** would read the live `ClusterPolicy`/`Policy` objects from the target cluster
  instead of files, so the gate matches admission exactly. That would need Kyverno installed in the target cluster and a
  read-only kubeconfig for it.
- Tested: harness fixtures in [`test/fixtures/kyverno-apply`](../../../../test/fixtures/kyverno-apply).

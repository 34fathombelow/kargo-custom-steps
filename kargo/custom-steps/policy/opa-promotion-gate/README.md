# opa-promotion-gate

Applies an OPA/Rego policy to the **promotion itself** rather than to manifests: who is promoting, to which Stage, when,
whether it is a rollback, plus any facts you pass in (environment, change ticket, ...). Use it for organization-specific
rules on top of Kargo's RBAC, such as "only release managers promote to prod", "no prod promotions on Friday afternoon"
or "prod needs a change ticket".

## Prerequisites

Beyond the [common prerequisites](../../../../README.md#prerequisites):

| | |
|---|---|
| Cluster add-ons | None (OPA runs as a CLI in the step) |
| Reachable services | None |
| Accounts / credentials | None (git credentials only if the policy repo is private, for `git-clone`) |
| Kargo capabilities | None |
| Network egress | None |
| Inputs | The Rego policy in the workdir, e.g. from `git-clone` |

## Config

| Key | Type | Required | Default | Description |
|---|---|---|---|---|
| `policyPath` | string | yes | — | Workdir-relative `.rego` file or directory |
| `query` | string | no | `data.kargo.promotion` | Query to evaluate. Its value must be an object with `allow` (bool) and `reasons` (list of strings) |
| `input` | map | no | `{}` | Extra facts merged into the input document (e.g. `environment`, `change_ticket`) |
| `now` | string | no | current time | RFC 3339 time to evaluate instead of now. For testing |

### The input document

| Field | Source |
|---|---|
| `project`, `stage`, `promotion` | Promotion context |
| `actor` | Who started the promotion (`ctx.meta.promotion.actor`) |
| `rollback` | Whether this is a rollback promotion |
| `freight` | `{name, alias, origin: {name}}` of the Freight being promoted |
| `timestamp`, `weekday` (`Mon`..`Sun`), `hour` (0–23) | Evaluation time, UTC |
| everything in `config.input` | The promotion template. Promotion context fields always win, so `input.actor` cannot be spoofed |

## Outputs

| Key | Type | Description |
|---|---|---|
| `allowed` | bool | `true` only if the policy's `allow` is exactly `true` |
| `reasons` | list | The policy's denial reasons |
| `input` | object | The input document that was evaluated, for auditing |

## Example

```yaml
steps:
- uses: git-clone
  config:
    repoURL: https://github.com/example/platform-policies.git
    checkout:
    - branch: main
      path: ./policies
- uses: opa-promotion-gate
  as: policy
  config:
    policyPath: ./policies/promotion
    input:
      environment: prod
      # quote(): a numeric ticket like 12345 would otherwise become a number.
      change_ticket: ${{ quote(vars.changeTicket) }}
```

The example policy [`policy/opa/promotion/promotion.rego`](../../../../policy/opa/promotion/promotion.rego) shows the
contract: a `deny` set of messages, `allow if count(deny) == 0`, rollbacks always allowed, `default allow := false`.

## Try it

Demo project `custom-steps-policy` ([kargo/projects/policy](../../../projects/policy)):

| Stage | Input | Expected |
|---|---|---|
| `promotion-allowed` | `environment: dev` | Succeeds: `allowed: true` |
| `promotion-denied` | `environment: prod`, no change ticket | Fails, listing every reason: you are not in `release_managers`, no change ticket (and, on Friday afternoons, the Friday rule) |

Rollbacks are always allowed by the demo policy: the `rollback-allowed` fixture shows it.

## Notes

- Read-only and idempotent, so retries are safe.
- An undefined query (wrong package name) fails the step instead of silently allowing.
- For a *human* approval rather than a policy decision, use Kargo Enterprise's built-in `wait-for-approval` step.
- Tested: harness fixtures in [`test/fixtures/opa-promotion-gate`](../../../../test/fixtures/opa-promotion-gate).

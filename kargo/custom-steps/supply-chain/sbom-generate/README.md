# sbom-generate

Writes an SBOM (software bill of materials: every package in an image, with its version and license) for an image
being promoted, with [Syft](https://github.com/anchore/syft), into the promotion workdir next to the rendered manifests.
Optional deny rules block the promotion when the image contains a package the team doesn't ship, such as an
end-of-life OpenSSL.

An SBOM recorded on each promotion answers "what is running in this environment, and since when?". When a vulnerability
is announced in a library, searching the SBOMs shows which promoted images contain it, including images you didn't
build. Later steps can commit the file next to the manifests, upload it, or scan it.

## Prerequisites

Beyond the [common prerequisites](../../../../README.md#prerequisites):

| | |
|---|---|
| Cluster add-ons | None |
| Reachable services | The image's registry |
| Accounts / credentials | None for public images. Private registries are not supported |
| Kargo capabilities | None |
| Network egress | The image's registry, to pull the image |
| Inputs | None; the image comes from the Freight, ideally by digest |

## Image

`ghcr.io/34fathombelow/syft:1.55.0`, built from [`docker/syft/Dockerfile`](../../../../docker/syft/Dockerfile) and published by this repo's
GitHub Actions:

```dockerfile
# Syft for the Kargo sbom-generate custom step: it pulls an image from its
# registry (no Docker daemon) and writes its SBOM. bash and jq summarize the SBOM
# and check it against the step's deny rules.
# renovate: datasource=docker depName=ghcr.io/anchore/syft
ARG SYFT_VERSION=1.55.0
# renovate: datasource=docker depName=alpine
ARG ALPINE_VERSION=3.24.2

FROM ghcr.io/anchore/syft:v${SYFT_VERSION} AS syft

FROM alpine:${ALPINE_VERSION}
ARG SYFT_VERSION
LABEL org.opencontainers.image.source=https://github.com/34fathombelow/kargo-custom-steps \
      org.opencontainers.image.description="Syft (SBOM generator) for the Kargo sbom-generate custom step" \
      org.opencontainers.image.version=${SYFT_VERSION}
RUN apk add --no-cache bash ca-certificates jq
COPY --from=syft /syft /usr/local/bin/syft
# Custom steps run as 65532 with a read-only view of most of the filesystem;
# Syft unpacks image layers and caches under a writable /tmp.
ENV HOME=/tmp \
    TMPDIR=/tmp \
    SYFT_CHECK_FOR_APP_UPDATE=false
USER 65532:65532
```

## Config

| Key | Type | Required | Default | Description |
|---|---|---|---|---|
| `image` | string | yes | — | Image to describe, ideally by digest: `${{ imageFrom(repo).RepoURL + "@" + imageFrom(repo).Digest }}` |
| `outPath` | string | yes | — | Workdir-relative file to write, e.g. `./out/sbom/app.spdx.json`. Replaced if it exists |
| `format` | string | no | `spdx-json` | `spdx-json`, `cyclonedx-json` or `syft-json` |
| `platform` | string | no | `linux/amd64` | Platform of a multi-arch image to describe |
| `deny` | list | no | `[]` | Rules `{name, version, license, reason}`. `name`, `version` and `license` are regular expressions; a package that matches every field a rule sets is denied, and any denied package blocks the promotion |

For example, to block images that still ship OpenSSL 1.1.x or anything under the AGPL:

```yaml
deny:
- name: "^(openssl|libssl)"
  version: "^1\\.1\\."
  reason: OpenSSL 1.1.x is end-of-life
- license: "AGPL"
  reason: AGPL code is not allowed in this product
```

## Outputs

| Key | Type | Description |
|---|---|---|
| `passed` | bool | False when a package matches a deny rule |
| `image` | string | The image described |
| `digest` | string | The image's manifest digest |
| `format` | string | The SBOM format |
| `path` | string | Where the SBOM was written (workdir-relative) |
| `packages` | number | Number of packages in the image |
| `byType` | map | Packages by type, e.g. `{apk: 16}` or `{deb: 135, java-archive: 1}` |
| `licenses` | map | The 10 most common declared licenses, with their package counts |
| `denied` | list | `{name, version, type, licenses, reason}` for each denied package (first 50) |
| `deniedCount` | number | Number of denied packages |
| `truncated` | bool | Whether `denied` was cut at 50 |
| `error` | string | Why the step failed; empty on success |

The full SBOM is in the file, not the output: SBOMs of large images run to megabytes, and step outputs are capped at
256 KiB.

## Example

```yaml
steps:
- uses: sbom-generate
  as: sbom
  config:
    image: ${{ imageFrom("ghcr.io/example/app").RepoURL + "@" + imageFrom("ghcr.io/example/app").Digest }}
    outPath: ./out/sbom/app.spdx.json
    deny:
    - name: "^(openssl|libssl)"
      version: "^1\\.1\\."
      reason: OpenSSL 1.1.x is end-of-life
```

| Stage | Expected |
|---|---|
| `sbom-generate-pass` | Promotion succeeds. The `sbom` output reports alpine 3.24.2's 16 packages (`byType: {apk: 16}`) and `passed: true` |
| `sbom-generate-blocked` | Promotion fails. nginx 1.20.0 still ships OpenSSL 1.1.1d, so `denied` lists `openssl` and `libssl1.1` with the rule's reason. The SBOM is still written |

## Notes

- Syft pulls the image straight from its registry (no Docker daemon). One run writes the requested format and a
  `syft-json` copy the step summarizes.
- The SBOM is written before the deny rules are checked, so a blocked promotion still leaves the evidence behind.
- Deny rules match with regular expressions rather than version ranges, because version schemes differ across
  ecosystems (Debian, Alpine, npm, Go...). Anchor them (`^...`) to avoid matching too much.
- Licenses are the ones packages declare; packages without license metadata don't match `license` rules.
- Tested: harness fixtures in [`test/fixtures/sbom-generate`](../../../../test/fixtures/sbom-generate), against public
  images on `mirror.gcr.io`.

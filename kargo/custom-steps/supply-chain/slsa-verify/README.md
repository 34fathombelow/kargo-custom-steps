# slsa-verify

Verifies the [SLSA](https://slsa.dev) build provenance of an image, or of release files in the workdir, with
[slsa-verifier](https://github.com/slsa-framework/slsa-verifier): that a trusted builder built it **from the source
repository you expect**, and optionally from a given tag, tag series, branch, commit, builder or set of workflow
inputs. Missing provenance, or provenance that doesn't match, blocks the promotion. A signature (`cosign-verify`) shows who signed an image;
provenance shows where and how it was built.

## Prerequisites

Beyond the [common prerequisites](../../../../README.md#prerequisites):

| | |
|---|---|
| Cluster add-ons | None |
| Reachable services | None |
| Accounts / credentials | Registry credentials only for private images (`username` / `password`) |
| Kargo capabilities | None |
| Network egress | The Sigstore TUF root at `tuf-repo-cdn.sigstore.dev`, and for images their registry. Rekor and Fulcio are not contacted: the provenance carries its transparency-log proof |
| Inputs | Images with SLSA provenance from a builder slsa-verifier supports, such as the [slsa-github-generator](https://github.com/slsa-framework/slsa-github-generator) container workflow. For `artifacts`: the files and their provenance file in the workdir, put there by an earlier step |

## Config

| Key | Type | Required | Default | Description |
|---|---|---|---|---|
| `image` | string | one of | — | Image to verify, **by digest**: `${{ imageFrom(repo).RepoURL + "@" + imageFrom(repo).Digest }}`. A tag reference is refused |
| `artifacts` | list or string | one of | — | Workdir files to verify instead, e.g. release binaries or an SBOM. One provenance file must cover all of them |
| `provenancePath` | string | with `artifacts` | — | Workdir provenance file, e.g. `<name>.intoto.jsonl` from the release. With `image`, used instead of the registry (Google Cloud Build provenance, downloaded by an earlier step) |
| `sourceUri` | string | yes | — | Repository it must be built from, e.g. `github.com/org/repo` (`https://` is optional) |
| `sourceTag` | string | no | — | Exact git tag it must be built from. Pass the Freight's image tag (`${{ imageFrom(repo).Tag }}`) to check that the tag matches the source |
| `sourceVersionedTag` | string | no | — | A semver prefix the tag must match instead, e.g. `v1` or `v1.2`. Not with `sourceTag` |
| `sourceBranch` | string | no | — | Branch it must be built from. Not every GitHub workflow trigger records one |
| `sourceCommit` | string | no | — | Commit it must be built from: the full SHA, or a prefix of at least 7 characters. slsa-verifier has no flag for this, so the step compares it with the verified provenance |
| `builderId` | string | no | — | Trusted builder, e.g. `https://github.com/slsa-framework/slsa-github-generator/.github/workflows/generator_container_slsa3.yml` (with or without `@<ref>`). Required by slsa-verifier for Google Cloud Build (`https://cloudbuild.googleapis.com/GoogleHostedWorker`) |
| `buildWorkflowInputs` | map | no | — | Inputs a `workflow_dispatch` build must have been triggered with, e.g. `{release: "true"}`. Builds from other triggers fail |
| `provenanceRepository` | string | no | — | Image only: `<registry>/<repository>` holding the provenance, when it isn't stored next to the image |
| `username`, `password` | string | no | — | Image only: registry credentials, e.g. `${{ secret('registry').password }}` |

## Outputs

| Key | Type | Description |
|---|---|---|
| `verified` | bool | Whether verification succeeded |
| `image` | string | The image that was verified (empty for artifacts) |
| `digest` | string | Its digest |
| `artifacts` | list | The files that were verified (empty for an image) |
| `sourceUri` | string | The source repository the step expected |
| `builderId` | string | The builder that produced the provenance |
| `sourceRepo` | string | The repository the provenance says the image was built from |
| `ref` | string | The git ref it was built from, e.g. `refs/tags/v1.2.3` |
| `commit` | string | The commit it was built from |
| `workflow` | string | The workflow file that ran the build |
| `predicateType` | string | The SLSA provenance version |
| `links` | list | The source commit and the CI run, rendered as links in the Kargo UI (GitHub builds) |
| `error` | string | Why verification failed (empty on success) |

When verification fails the step **fails** and the promotion stops. `error` (and the step message) give
slsa-verifier's reason, including the actual tag, source or builder when it differs from the expected one. The
provenance fields are empty on failure, except after a commit mismatch.

## Example

```yaml
steps:
- uses: slsa-verify
  as: provenance
  config:
    image: ${{ imageFrom('ghcr.io/example/app').RepoURL + "@" + imageFrom('ghcr.io/example/app').Digest }}
    sourceUri: github.com/example/app
    sourceTag: ${{ imageFrom('ghcr.io/example/app').Tag }}
```

Release files, with the provenance the release publishes next to them (as Argo CD does for its CLI and SBOM). An
earlier step downloads them into the workdir:

```yaml
- uses: slsa-verify
  as: cli-provenance
  config:
    artifacts: [./bin/argocd-linux-amd64]
    provenancePath: ./bin/argocd-cli.intoto.jsonl
    sourceUri: github.com/argoproj/argo-cd
    sourceTag: v3.5.6
```

## Notes

- Covers slsa-verifier's `verify-image` and `verify-artifact`. Not covered: `verify-npm-package` (experimental),
  `verify-github-attestation` (limited to a few Bazel builders) and `verify-vsa`.
- Only GitHub repositories work as `sourceUri` for GitHub builders. Google Cloud Build provenance also accepts the
  Cloud Storage source bucket (`gs://...`).
- slsa-verifier also checks that the image or file digest matches the provenance subject, so a re-pushed tag or a
  modified file fails.
- Read-only, so retries are safe.
- The step never shows the provenance's GitHub actor, only the repository, ref, commit and workflow.
- Tested: harness fixtures in [`test/fixtures/slsa-verify`](../../../../test/fixtures/slsa-verify).
